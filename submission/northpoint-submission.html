The Problem & The Solution

Northpoint Living's online store runs on a single server. When it fails, everything stops — especially during sales campaigns. Here's what changes:

❌ Current State (Risky)

  • 99.2% uptime (failed 2× last year)
  • No backups tested
  • No auto-scaling
  • Manual file uploads to deploy
  • No monitoring or alerts
→

✅ New State (Resilient)

  • 99.9% uptime (auto-heals)
  • Continuous backups every second
  • Auto-scales for 10× traffic
  • Git push = auto deploy + rollback
  • Real-time monitoring & alerts
Key insight for non-technical readers: Think of the current setup like a single delivery truck carrying ALL goods. If it breaks down, everything stops. The new setup is like a fleet of trucks managed by a dispatch service — if one breaks, the rest keep delivering. And the fleet automatically grows during busy periods.

D. Automation — How Deployments Work

How code gets from the developer to the live store

Terraform Infrastructure-as-Code (representative excerpt)

resource "google_cloud_run_v2_service" "storefront" {
  name     = "northpoint-storefront"
  location = "asia-east2"          # Hong Kong

  template {
    scaling {
      min_instance_count = 2       # Always 2 for high availability
      max_instance_count = 50      # Hard cap to control cost
    }

    containers {
      image = "asia-east2-docker.pkg.dev/.../storefront:latest"
      resources {
        limits = { cpu = "2", memory = "4Gi" }
      }

      # Secrets from Secret Manager — never hardcoded
      env {
        name = "DB_PASSWORD"
        value_source {
          secret_key_ref {
            secret  = google_secret_manager_secret.db_password.secret_id
            version = "latest"
          }
        }
      }

      # Health check — auto-restart if unhealthy
      liveness_probe {
        http_get { path = "/api/health" }
        period_seconds = 30
      }
    }
  }
}

Pre-Migration: Existing Server Backup Plan

⚠️ Rule #1: NEVER touch the existing server without a full verified backup first. The current VPS is a single point of failure — one mistake and both the live site AND the data could be lost.

The current Northpoint Living server is a single VPS running PHP (WooCommerce), MySQL database, and 180GB of product media files — all on one machine with no backups, no redundancy, and no failover.

Data Migration: Old VPS → New GCP

Flow: Old VPS → mysqldump → SQL file → gsutil cp → Cloud Storage → gcloud sql import → Cloud SQL
Media: Old VPS → gsutil -m cp -r → Cloud Storage bucket (parallel upload, ~2-4 hours for 180GB)
Key principle: The old VPS server is NEVER modified or deleted until 30 days after successful migration. It serves as the instant rollback target — just switch DNS back (60-second propagation with pre-lowered TTL).

Design Rationale: Why Cloud Run, Not Kubernetes

❌ GKE Kubernetes

  • Requires node/VM management
  • Over-engineered for 1 application
  • Nodes run 24/7 (even idle) — expensive
  • 50+ YAML config files
  • Needs dedicated DevOps team
  • Cost: ~HKD 4,500+/month
→

✅ Cloud Run (Our Choice)

  • Zero server management
  • Auto-scales 2→50 instances
  • Pay per use (idle = almost free)
  • Just 1 Dockerfile needed
  • 1 person sufficient for ops
  • Cost: ~HKD 2,184/month
Fully Managed = Google handles: OS patching, security updates, automated backups, HA failover, disk encryption (AES-256), auto-scaling, auto-healing, monitoring. Cloud SQL requires zero MySQL installation — configure via Terraform, Google runs it. The Dockerfile is a recipe for packaging the app; Cloud Run is the kitchen that cooks and serves it.
