Rollback Decision Matrix

🔴 ABORT Smoke tests fail

Restore DNS to VPS IP immediately. No data modified on old system. DevOps lead decides.

🟡 REVERT Error rate > 5% in first 2h

Revert DNS (60s TTL = fast). Export Cloud SQL data, replay on VPS. IT Manager + DevOps decide jointly.

🔵 MONITOR Minor issues, < 5% errors

Stay on new platform, investigate & hotfix. Rollback only if unresolved after 4h.

🟣 CLIENT CALL Critical business function broken

Immediate rollback regardless of metrics. Client + IT Manager decide jointly.

F. Risk Register — Top 5 Risks

Likelihood × Impact matrix · Includes agency risk (#5)

Risk Matrix

1

Campaign spike exceeds 10× estimate

Med likelihood High impact
Mitigation: Set max_instances=50 (not 20). Pre-provision read replica. Load-test at 15× before each campaign. Cloud Armor rate-limits bot traffic.
2

Data breach / PDPO non-compliance

Low likelihood Critical impact
Mitigation: All data in asia-east2 (HK). AES-256 encryption at rest, TLS in transit. VPC Service Controls. Access logging on all admin ops. Annual PDPO review.
3

Bad deployment breaks production

Med likelihood High impact
Mitigation: Blue-green deploy: new revision gets 0% traffic until smoke test passes. Instant rollback via gcloud CLI. Canary → full rollout pipeline.
4

Cloud SQL failover exceeds 60s RTO

Low likelihood Med impact
Mitigation: RTO target is 60 min, not 60 sec. Even a 5-min failover is well within RTO. Cloud Run retries automatically. CDN serves cached pages during the gap.
5

🏢 Agency key-person risk (Visible One)

Med likelihood High impact
Mitigation: All infra is in Terraform (reproducible). Runbooks in shared wiki. CI/CD pipeline = no deep knowledge needed for deploys. Cross-train at least 1 other engineer within 60 days.
