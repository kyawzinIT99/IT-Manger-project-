Rollback Decision Matrix

🔴 ABORT Smoke tests fail

Restore DNS to VPS IP immediately. No data modified on old system. DevOps lead decides.

🟡 REVERT Error rate > 5% in first 2h

Revert DNS (60s TTL = fast). Export Cloud SQL data, replay on VPS. IT Manager + DevOps decide jointly.

🔵 MONITOR Minor issues, < 5% errors

Stay on new platform, investigate & hotfix. Rollback only if unresolved after 4h.

🟣 CLIENT CALL Critical business function broken

Immediate rollback regardless of metrics. Client + IT Manager decide jointly.

💾 Existing Server Backup & Data Extraction Plan

Before touching anything — full backup of the current VPS (single server: PHP app + MySQL + 180GB media files)

⚠️

Current State (Single VPS)

📋 Pre-Migration Backup Steps

1

Full VPS Snapshot

Take a full disk snapshot of the entire VPS via hosting provider panel. This captures OS + app + DB + files.

2

MySQL Database Dump

mysqldump --all-databases --single-transaction --routines --triggers > full_backup.sql

3

Media Files Archive

tar -czf media_backup.tar.gz /var/www/uploads/
Or use rsync for incremental: rsync -avz

4

Application Code Backup

tar -czf app_backup.tar.gz /var/www/html/
Plus config files: .env, wp-config.php, nginx.conf

5

Verify & Store Off-Site

Verify checksums. Upload to GCS bucket + local external drive. Two copies minimum.

🔄 Data Migration Flow

✅ Backup Verification Checklist

☑ VPS snapshot created & verified (hosting panel)
☑ MySQL dump completed — row counts match live DB
☑ Media files: file count + total size verified (180GB)
☑ App configs backed up (.env, wp-config, nginx, crontab)
☑ SSL certificates exported (if self-managed)
☑ DNS records documented (A, CNAME, MX, TXT)
☑ Cron jobs documented & migrated to Cloud Scheduler
☑ Backups stored in 2 locations (GCS + local drive)

🛡️ Safety Net During Migration

✅ Old VPS stays running for 30 days

Don't delete the old server. It runs in parallel as a warm standby. If anything goes wrong → switch DNS back in 60 seconds.

🔄 Daily DB sync: Cloud SQL → VPS

During the 30-day parallel run, export Cloud SQL daily and replay on the old VPS. Ensures rollback is always current.

⏱️ DNS TTL lowered to 60s before cutover

48 hours before migration, reduce DNS TTL. This means rollback takes effect in 1 minute, not 24 hours.

📊 Decommission criteria (Day 30)

Only delete old VPS after: 0 error spikes, all functionality verified, client sign-off obtained.

📟 Key Commands Reference

# Database backup
mysqldump -u root -p --all-databases --single-transaction > backup.sql
# Upload media to GCS
gsutil -m cp -r /var/www/uploads/* gs://northpoint-media-bucket/
# Import DB to Cloud SQL
gcloud sql import sql northpoint-db gs://bucket/backup.sql
